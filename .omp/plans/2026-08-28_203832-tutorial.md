# Seamless Onboarding Tutorial — Implementation Plan

> **Handoff:** Use omp `task` subagents to implement this plan task-by-task.

**Goal:** A first-time-player tutorial that teaches the game's core loop
(mine → clean → assemble → fund → defend → hire) through short, event-driven
coach steps with canvas highlights and finance-native tips — seamless (never a
modal wall, never blocks play), skippable, resumable.

**Architecture:** A `Tutorial` controller owns an ordered list of steps. Each
step has a trigger predicate over `World`, a coach card (DOM), and an optional
canvas highlight (ring/arrow drawn in world space next to entities). Steps
advance only when the player *does the thing* — no "press next" walls. Progress
persists as an optional save field (in-repo convention: `writtenOff?`), so an
autosave resume picks up where the player left off.

**Tech stack:** Existing stack only — TypeScript strict, Vitest for the pure
step logic, DOM test pattern (like `src/ui/panel.dom.test.ts`), no runtime
deps, no new canvas layer.

## Design contract (what the tutorial IS)

1. **Event-driven, not time-driven.** A step completes when its predicate on
   `World` is true. Player acts → world changes → step flips. The only
   timed element is a fade-out (~300 ms) on completion.
2. **Never blocks.** The coach card is a passive DOM element; build/HUD input
   is never intercepted. No step requires clicking the card.
3. **Seamless entry.** Shows automatically on a *fresh world with no buildings
   placed* and no resumed save. Never in `?demo`. Never re-shows on a load
   where it already completed or was skipped.
4. **Tips are numbers-of-record.** Every quoted number comes from
   `DESIGN.md §11` (costs, payback ~109 s for the first line, hire comp,
   wave cadence). No vibes-based advice.
5. **Visuals in-repo.** Highlight = pulsing ring + arrow drawn on the game
   canvas in world space (same palette as `entity-render.ts`: cyan
   `#00C8FF` selection, amber `#FFB300` alarms). Chain diagram in the card =
   inline HTML chips (`▸ TAPE ▸ CLEAN ▸ …`) styled with existing CSS tokens.
   No image assets, no new fonts.
6. **Failure-aware.** When brownout (`world.multiplier < 1`) or a machine is
   starved (built but not `workedLastTick`), any step may *pause* and show its
   one-line troubleshooting tip, then resume. One tip slot, reused.

- Contextual pause-tips (same slot, one line): "Brownout: build Funding Desks
  and Treasury Vaults (8/9) — power is capital." / "Starved line: a machine

## Risks / tradeoffs

- **Predicate fragility:** step triggers read World internals; if sim fields
  change, tests catch it — predicates are the tutorial's only coupling point
  (by design, one file).
- **Timer step (step 0) feels gamey:** mitigation — movement completes it
  instantly; timeout only prevents a dead stop. Alternative (no timeout)
  risks a stuck first impression.
- **Not persisting skipped state per-profile:** skipped is remembered in the
  save only; a player who clears storage sees it again — acceptable
  (matches Factorio behavior, boring default).
- **Highlight in world space vs second canvas:** chose existing canvas —
  zero new layers, follows entity-render conventions; risk: must not allocate
  in the hot path (plan enforces).
- **Open question for owner:** should step 7 (hire) highlight the actual bro
  (it moves) or the HQ? Plan defaults to "nearest bro, falls back to HQ" —
  say the word if you want it pinned to HQ.
